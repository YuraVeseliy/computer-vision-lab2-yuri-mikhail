# Практическое задание 2 «Статистика по изображению»

Команда: **Юрий и Михаил**. Запускаемый файл: `main.py`.

Реализованы все восемь пунктов задания. Математика написана обычными
циклами Python. В математических модулях нет NumPy, OpenCV, готовых
гистограмм, среднего, дисперсии, фильтров или преобразований Pillow.
Pillow отвечает только за загрузку, сохранение и экранное представление.
Tkinter отвечает за окно программы, кнопки и графики.

## Перенос в PyCharm

1. На странице репозитория выберите **Code → Download ZIP** и распакуйте
   архив. Либо клонируйте репозиторий через **Get from VCS** в PyCharm.
2. Откройте в PyCharm папку проекта, в которой находятся `main.py` и
   `requirements.txt`. Все восемь основных Python-файлов должны оставаться
   в общем корне: импорты рассчитаны именно на такое размещение.
3. Создайте своё виртуальное окружение `.venv`. Проект проверен на
   Python 3.13. Окружение и личные настройки интерпретатора в репозиторий
   не включены; общий профиль инспекций PyCharm включён.
4. В терминале **этого проекта PyCharm**, с активным `.venv`, выполните:

   ```console
   python -m pip install -r requirements-dev.txt
   ```

   Установятся Pillow для загрузки и отображения и `pycodestyle` для
   проверки оформления. `pycodestyle` не участвует в математике.
   Для одного запуска приложения достаточно `requirements.txt`.

5. Откройте `main.py`, нажмите правой кнопкой в редакторе и выберите
   **Run 'main'**. Если PyCharm сообщает об отсутствии Pillow, проверьте,
   что установка пакета и запуск используют один Project venv.
6. Нажмите «Учебный пример». Затем попробуйте открыть своё RGB PNG/BMP/TIFF.

В стандартной установке Python на Windows Tkinter уже доступен.
Если модуль `tkinter` отсутствует, установите компонент Tcl/Tk в установщике
Python. Отдельного пакета `tkinter` для установки через pip не требуется.

## Равное распределение основных файлов

У каждого ровно четыре основных Python-файла. Разделение основано на
обязанностях: Юрий отвечает за статистику и представление данных,
Михаил — за обработку изображения и управление программой.
Объём основных файлов также близок: примерно 550 строк у каждого,
включая пояснения и пустые строки.

| Юрий | Назначение | Михаил | Назначение |
|---|---|---|---|
| `statistics_ops.py` | Яркость, гистограммы, две формулы дисперсии, окно, профиль, пример | `image_ops.py` | Яркость/контраст, негатив, гамма, обмен, зеркала, размытие, карта |
| `image_io.py` | Чтение, проверка формата, запись, передача пикселей Pillow | `application.py` | Исходное/текущее изображение, параметры, события, вызовы операций |
| `view_widgets.py` | Прокрутка изображения, рамка 13×13, рисование графиков | `editor_controls.py` | Кнопки и поля редактирования, выбор способа расчёта дисперсии |
| `analysis_views.py` | Вкладки, обновление представлений, подпись окна и профиль | `main.py` | Создание окна и запуск цикла событий |

В начале каждого основного файла указан владелец.
`tests/test_algorithms.py`, `README.md` и `DEFENSE.md` — общие материалы
проверки и подготовки, в восемь основных файлов программы не входят.
Это предложенное распределение: перед сдачей каждый должен самостоятельно
разобрать свою часть и уметь объяснить её строки и вызовы.

В требованиях преподавателя отдельно сказано: алгоритмы этой работы должны
знать **оба**, независимо от распределения кода. Поэтому разделение личного
объяснения кода не отменяет общих вопросов по алгоритмам и базовой математике.

## Формулы и договорённости

- Яркость **строго по заданию**: `I=(R+G+B)/3`. Для расчётов она остаётся
  дробной. Для вывода серого и корзин гистограммы округляется до 0..255.
  В лекции 1 также обсуждается взвешенное RGB→серое; здесь используется
  формула, явно заданная в практическом задании и лекции 2_1.
- Дисперсия делится на **N**, как в лекции 2_1; это не оценка с N−1.
  Оба способа расчёта доступны в переключателе.
- Окно мыши всегда имеет заданный размер 11×11. На границе берём его
  пересечение с изображением и делим на фактическое число пикселей.
  N показано пользователю. В центре N=121, в углу большого изображения N=36.
- Рамка — внешнее кольцо 13×13 с внутренним отверстием 11×11. Она не входит
  в массив изображения и не влияет на статистику или сохраняемый файл.
- Размытие учитывает **центр** и соседей: 5 или 9 точек внутри изображения.
  На границах усредняются существующие точки. Все значения читаются из
  старого массива, записываются в новый.
- Карта контрастности следует лекции 2_1, слайд 11:
  `C(p)=abs(I(p)−mean(neighbors))`; общая контрастность — среднее карты.
  Центр исключается из соседей. Для 1×1 соседей нет, принимается C=0.
  Это не дисперсия и не среднее модулей отдельных разностей.
- Для квадратной окрестности используется вручную построенная таблица
  сумм. Она даёт ту же сумму окна за четыре обращения к таблице,
  поэтому большой размер окна не требует повторно складывать все его
  пиксели для каждой позиции. Формула карты от этого не меняется.
- Карта показывается в шкале 0..255 без усиления. Значения C доступны
  при движении мыши по карте, даже когда небольшие различия плохо видны.
- Контраст редактируется относительно общего среднего I либо среднего
  выбранного канала. Негатив всех RGB даёт ровно `I'=255−I`.
- Исходное изображение хранится отдельно. Профиль берётся именно из него;
  каналы, гистограммы, сохранение и карта относятся к текущему варианту.

Работа рассчитана на **8-битные RGB-каналы**. PNG/BMP/TIFF с потерями,
прозрачностью или большей глубиной не преобразуются молча; неподдерживаемый
вариант отклоняется. Палитровый PNG без прозрачности раскрывается в RGB.
В многостраничном TIFF берётся первый кадр. PNG/BMP сохраняются в своём
формате, TIFF — без сжатия. Метаданные исходного файла не копируются.

Из-за ручных циклов большие фотографии обрабатываются медленнее.
Для первой демонстрации удобно использовать учебный пример или RGB
изображение порядка 512×512 пикселей. Уменьшенные картинки на вкладке
гистограмм — только превью; вычисления идут по полному массиву.

## Проверка перед сдачей

1. В PyCharm: `Ctrl+Alt+S → Editor → Inspections`. Оставьте проверки Python
   и PEP 8 включёнными; предупреждения об опечатках можно выключить,
   как разрешено преподавателем.
   В текущем проекте выбран профиль **Project Default**: проверки Python,
   типов, импортов и обе проверки PEP 8 включены. Для PEP 8 установлен
   уровень предупреждения. Отключено только предложение загрузить русский
   словарь (`LanguageDetectionInspection`); это не проверка кода Python.
   Русские пояснения перенесены на короткие строки: встроенный проверяющий
   модуль этой Windows-установки неверно декодирует UTF-8 при чтении stdin
   и считает длины по байтам. Отдельная проверка `pycodestyle` читает файлы
   корректно и проверяет ограничение 79 символов без исключений.
2. Для форматирования: `Code → Reformat Code` или `Ctrl+Alt+L`.
3. Выполните `Code → Inspect Code` для проекта. Каждое предупреждение
   исправьте либо подготовьте конкретное объяснение, почему оно допустимо.
   Массово выключать проверки для чистого индикатора не нужно.
4. Запустите общие тесты и проверку PEP 8 из корня проекта:

   ```console
   python -W error -m unittest discover -s tests -v
   python -m pycodestyle --max-line-length=79 --exclude=".venv,venv,.git,.idea,__pycache__" .
   python -m pip check
   ```

   `-W error` превращает предупреждения времени выполнения в ошибки;
   эти проверки дополняют инспекции PyCharm.

5. Пройдите все строки таблицы соответствия выше. Сохраните обработанный
   PNG, откройте его заново и убедитесь, что рамка в файл не попала.
6. Разберите свою часть по `DEFENSE.md` и повторите общие алгоритмы.
7. Возьмите бумагу и ручку или подготовьте привычное средство рисования.

Проверки синтаксиса, математические тесты и вызовы обработчиков Tkinter
выполнялись при подготовке проекта. Инспекции в вашей установке PyCharm
нужно выполнить отдельно после переноса кода.
